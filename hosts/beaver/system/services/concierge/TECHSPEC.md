# Concierge — Technical Specification

Status: **draft for approval**. Product intent: [PRODUCT.md](PRODUCT.md).

Host: `beaver` (aarch64-linux, NixOS 26.05, 8 GB RAM, system timezone UTC).
Repo: public `github.com:JustAlternate/nixcfg`, cfg root `/root/nixcfg` (mode 0700 on
`/root`, unreadable by unprivileged users — hence the snapshot design below).

## 1. Decisions

| Topic | Decision |
|---|---|
| Shape | One Go binary `concierge` + systemd units + timer |
| Privilege split | root collector (no network) → unprivileged analyzer (network) |
| Report | Markdown (canonical) + HTML + `findings.json`, one directory per week |
| Intel | vulnix (Nix store), osv-scanner (repo deps), CISA KEV (exploited) |
| Journal | append-only JSONL + hash chain, CLI subcommands, local first |
| Notify | Gotify (new dedicated app token) + local Postfix email |
| Silence detection | Grafana alert on `node_systemd_timer_last_trigger_seconds` |
| Default mode | `observe` (no mutation) |
| Language | user brief in French, identifiers/annex in English |

Not used: grype/syft/trivy (redundant with vulnix + OSV for this host), external SaaS,
public report portal.

## 2. Architecture

```
concierge.timer (Sun 04:00 Europe/Paris)
        │
        ▼
concierge-collect.service        root, no network, hardened
  ├─ host facts (systemd, ports, perms, backups, certs…)
  ├─ repo snapshot  /run/concierge/repo (+ bare mirror for history)
  └─ /run/concierge/collector.json
        │
        ▼
concierge-analyze.service        user concierge, network, no root
  ├─ lint/eval (nixfmt, deadnix, statix, nix flake check)
  ├─ gitleaks (worktree + history)
  ├─ osv-scanner + vulnix + CISA KEV
  ├─ severity mapping + allowlist + report render
  ├─ /var/lib/concierge/runs/<YYYY>-W<WW>/{report.md,report.html,findings.json,raw/}
  ├─ journal append
  └─ notify (Gotify/email)
        │
        ▼
concierge-notify-failure@.service  on any unit failure → CRITICAL notification
```

Failure isolation: the analyzer only parses untrusted network data (NVD/OSV/KEV) and
snapshots. It never runs as root and cannot read `/root` or sops secrets (except the
Gotify token, deliberately).

## 4. CLI

```
concierge collect  --out /run/concierge/collector.json
concierge analyze  --collector /run/concierge/collector.json \
                   --repo /run/concierge/repo --mirror /run/concierge/repo.git \
                   --config /etc/concierge.toml --out /var/lib/concierge/runs \
                   [--offline] [--no-notify] [--fixtures <dir>]
concierge report   --findings <file> --out <dir>          # re-render only
concierge journal  add|tail|search|handoff|verify|export
concierge allowlist lint [--file ...]
concierge selftest                                        # no network, no writes
```

Exit codes: `0` OK, `2` warnings, `3` critical findings, `1` internal error.
Units use `SuccessExitStatus=0 2 3`; only `1` makes the unit fail.

## 6. systemd units

Illustrative; hardening follows the mail-monitor template and repo rules.

### 6.1 `concierge-collect.service`

```nix
systemd.services.concierge-collect = {
  description = "Concierge — collect host facts (no network)";
  unitConfig.RequiresMountsFor = [ "/root/nixcfg" ];
  serviceConfig = {
    Type = "oneshot";
    User = "root";
    ExecStart = "${concierge}/bin/concierge collect --out /run/concierge/collector.json";
    UMask = "0027";
    PrivateNetwork = true;
    PrivateTmp = true;
    ProtectSystem = "strict";
    ProtectHome = "read-only";          # must read /root/nixcfg
    ReadWritePaths = [ "/run/concierge" ];
    NoNewPrivileges = true;
    CapabilityBoundingSet = "";
    RestrictAddressFamilies = [ "AF_UNIX" ];  # systemd dbus only
    RestrictNamespaces = true;
    RestrictSUIDSGID = true;
    LockPersonality = true;
    MemoryDenyWriteExecute = true;
  };
};
```

Repo snapshot (inside `collect`):

1. `git -C /root/nixcfg rev-parse HEAD`, `status --porcelain` (with
   `GIT_OPTIONAL_LOCKS=0`), `flake.lock` sha256.
2. Worktree copy of **tracked + untracked-but-not-ignored** files only (`.git`,
   `.opencode/node_modules`, `data/`, and other ignored paths excluded) to
   `/run/concierge/repo` (`git ls-files -z` + `--others --exclude-standard`).
3. `git clone --mirror /root/nixcfg /run/concierge/repo.git` for history scanning.
4. All of `/run/concierge` is `0640`/`0750`, readable by group `concierge`.

`/run/concierge` is created by tmpfiles (not `RuntimeDirectory`, which would be removed
between the two oneshot units and is owned `root:root`):

```nix
systemd.tmpfiles.rules = [
  "d /run/concierge 2770 root concierge -"          # setgid: group-readable outputs
  "d /var/lib/agent-journal 2770 root concierge -"   # setgid: entries inherit group
];
```

### 6.2 `concierge-analyze.service`

```nix
systemd.services.concierge-analyze = {
  description = "Concierge — analyze, report, journal, notify";
  requires = [ "concierge-collect.service" ];
  after = [ "concierge-collect.service" "network-online.target" ];
  wants = [ "network-online.target" ];
  onFailure = [ "concierge-notify-failure@%n.service" ];
  serviceConfig = {
    Type = "oneshot";
    User = "concierge";
    Group = "concierge";
    ExecStart = "${concierge}/bin/concierge analyze --config /etc/concierge.toml ...";
    StateDirectory = "concierge";
    StateDirectoryMode = "0750";
    CacheDirectory = "concierge";
    Environment = [ "HOME=/var/lib/concierge" "XDG_CACHE_HOME=/var/cache/concierge" ];
    UMask = "0027";
    TimeoutStartSec = "15min";
    PrivateTmp = true;
    ProtectSystem = "strict";
    ProtectHome = true;                 # /root hidden; snapshot lives in /run
    ReadOnlyPaths = [ "/run/concierge" "/nix/store" ];
    ReadWritePaths = [
      "/var/lib/concierge"
      "/var/cache/concierge"
      "/var/lib/agent-journal"
    ];
    NoNewPrivileges = true;
    CapabilityBoundingSet = "";
    RestrictAddressFamilies = [ "AF_UNIX" "AF_INET" "AF_INET6" ];
    RestrictNamespaces = true;
    RestrictSUIDSGID = true;
    LockPersonality = true;
  };
};
```

Static system user (needs persistent cache/state):

```nix
users.users.concierge = {
  isSystemUser = true;
  group = "concierge";
  home = "/var/lib/concierge";
  shell = pkgs.bash;   # no login; needed by some tools
};
users.groups.concierge = { };
```

`concierge` uses the Nix daemon for `nix flake check` (default `allowed-users = *`).
Verify with `nix config show allowed-users` before relying on it; if restricted, move
eval/lint checks to a third root unit instead of widening daemon access.

### 6.4 Failure notifier

Template unit running as root (Gotify token readable, no repo access). Sends
CRITICAL "concierge run failed" with unit name and last 20 journal lines. Exists so a
broken Sunday run is not discovered 8 days later.

## 7. Collector checks (root, no network)

All facts are written to `collector.json`, schema versioned. Best-effort: every check
records `{ok|error, duration_ms, error}` so the report can say what was not measured.

| ID | Fact | Method |
|---|---|---|
| HOST-01 | failed units | `systemctl list-units --failed --json` |
| HOST-02 | restart loops / NRestarts | `systemctl show -p NRestarts,ActiveEnterTimestamp` |
| HOST-03 | disk/inodes | `df -P`, `df -Pi` for `/`, `/var`, `/nix` |
| HOST-04 | RAM/swap/load/uptime | `/proc/meminfo`, `/proc/loadavg`, `/proc/uptime` |
| HOST-05 | NixOS generation + system path | `/run/current-system`, `nixos-rebuild list-generations --json` (if available) |
| HOST-06 | time sync | `timedatectl show` / `systemctl status systemd-timesyncd` |
| HOST-07 | SMART (best effort) | `smartctl` if a real device is present; skipped on virtio |
| SVC-01 | expected services active | unit list from config |
| SVC-02 | timer last trigger | `systemctl show <timer>.timer -p LastTriggerUSec` |
| SVC-03 | mail queue | `postqueue -p` count |
| SVC-04 | last backup run | last successful `restic-backups-beaver.service` / `postgresqlBackup` timestamp via systemd, not an SFTP query |
| SVC-05 | cert expiry | `openssl x509 -enddate` on `/var/lib/acme/*/fullchain.pem` |
| SVC-06 | resolver unit | `systemctl show kresd` state, restart count (DNS query is done by the analyzer) |
| SEC-01 | listeners + scope | `ss -Htulpn`, bind address, firewall config, tailscale0 |
| SEC-02 | firewall drift | compare `allowedTCPPorts` from evaluated config |
| SEC-03 | SSH config | `sshd -T` (effective): password auth, root login, max tries |
| SEC-04 | fail2ban | `fail2ban-client status` + current bans |
| SEC-05 | sudoers/doas | `visudo -c`, list files, check NOPASSWD |
| SEC-06 | users/keys | `/etc/passwd`, shells, `authorized_keys`, last logins |
| SEC-07 | SUID/world-writable | `find` over `/run/current-system/sw /usr/bin /etc` (skip `/nix/store`) |
| SEC-08 | secret perms | `secrets.yaml`, `/run/secrets/**`, age key (`/root/.config/sops/age/keys.txt`, 0600) |
| SEC-09 | opencode exposure | bind address + firewall rules + `tailscale0` trusted-interface check (no external probe needed) |
| SEC-10 | sops decrypt test | `sops -d secrets/secrets.yaml > /dev/null`, age key mode 0600 (root stage; analyzer never sees the key) |
| REPO-01… | repo facts | HEAD, dirty files, flake.lock hash, snapshot copy |

Listener scopes:

- `loopback` — bind 127.0.0.1/::1: informational.
- `public` — non-loopback bind AND port allowed by firewall: CRITICAL if not expected.
- `tailnet` — non-loopback bind reachable via `tailscale0`: WARN if not expected.

Expected listeners in `allowlist.toml`, e.g. 22/80/443/8443 (public), 4096 (opencode,
tailnet), service ports explicitly allowed on all interfaces (rauthy 8100/8200, sharry
3001…) with reason and expiry.

## 8. Analyzer checks (unprivileged, network)

### 8.0 Local probes (host network namespace)

These need the host network and therefore run in the analyzer, not the collector
(which has `PrivateNetwork=true`):

| ID | Check | Method |
|---|---|---|
| SVC-07 | firing Grafana alerts | Prometheus API `/api/v1/alerts` on `127.0.0.1:9001` |
| SVC-08 | resolver answers | DNS query to `127.0.0.1:53` for `justalternate.com` + `notif.justalternate.com` |
| SVC-09 | local HTTP health | optional HEAD checks on `127.0.0.1` service ports from config |

### 8.1 Repo hygiene

| ID | Check | Command / note |
|---|---|---|
| REPO-06 | formatting | `nixfmt . -c` on snapshot |
| REPO-07 | dead code / lint | `deadnix . -f`, `statix check .` |
| REPO-08 | flake evaluation | `nix flake check --no-build` (verify flag at impl; fallback `nix eval .#checks`) |
| REPO-09 | risky patterns | grep rules: plaintext secrets, `chmod 777`, `0.0.0.0` without justification, `PermitRootLogin yes`, `pkgs.unstable` without `# pin reason`, agent config with `bash/edit/webfetch: allow` |
| REPO-10 | docs drift | changed service file without matching README/RUNBOOK/AGENTS touch (heuristic, WARN) |
| REPO-11 | git state | dirty files, branch behind origin, flake.lock age |
| REPO-12 | home audit | same rules scoped to `home/` + `hosts/*/home/`; secrets never printed |
| REPO-13 | sops files shape | `secrets/*.yaml` contains `sops:` metadata and no obvious plaintext (metadata-only; the decrypt test needs the age key and runs in the collector, SEC-10) |
| REPO-14 | agent config review | `home/agent/opencode.json` permission block, tailnet-only service config |

### 8.2 Dependency and CVE intelligence

| ID | Check | Method |
|---|---|---|
| REPO-02 | secret leak, worktree | `gitleaks dir /run/concierge/repo --report-format json --redact` |
| REPO-03 | secret leak, history | `gitleaks git /run/concierge/repo.git --report-format json --redact` |
| REPO-04 | code deps | `osv-scanner scan source -r /run/concierge/repo --format json` |
| REPO-05 | Nix store | `vulnix --system --json --output ...` (flags confirmed at impl; see `vulnix --help`) |
| INTEL-01 | known exploited | CISA KEV feed, configurable URL; join CVE IDs from vulnix + OSV (`aliases`) |
| INTEL-02 | feed freshness | KEV `dateReleased`, vulnix DB mtime, OSV cache mtime; stale >14d = WARN |

Notes:

- `gitleaks` findings are reported even when redacted: a secret in a **public** repo is
  CRITICAL regardless of exploitability. The raw value never enters the report, email,
  journal, or logs.
- `osv-scanner` covers Go modules (`packages/*`, `mail-monitor`) and npm lockfiles that
  are actually committed. Local `.opencode/node_modules` is excluded (not repo content).
- `vulnix` reads `/nix/store` (world-readable) and needs network for NVD data unless a
  cache exists. Cache under `/var/cache/concierge/vulnix`. If NVD rate limits bite, add
  an optional sops secret `CONCIERGE/NVD_API_KEY` (not part of MVP).
- CISA KEV: `https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json`
  (official feed; URL configurable). KEV match on an installed/affected version is the
  highest-signal CRITICAL we can produce.
- Network calls: 3 attempts, exponential backoff, 30 s connect / 120 s total each;
  failures mark the check `error`, never "clean".

## 9. Findings, severity, allowlist

Finding model (`findings.json`):

```json
{
  "id": "SEC-01:4f3c2a91b7d0e6c8",
  "check": "SEC-01",
  "severity": "critical",
  "subject": "listener:0.0.0.0:8200/rauthy",
  "title": "Unexpected public listener",
  "why": "Reachable from the internet and not in the expected listener list.",
  "action": "Bind to 127.0.0.1 or add an explicit exception with expiry.",
  "evidence": { "bind": "0.0.0.0", "port": 8200, "scope": "public" },
  "cves": [],
  "allowlisted": false,
  "first_seen": "2026-10-24",
  "last_seen": "2026-10-24"
}
```

`id = "<check>:<first 16 hex of sha256(check|subject|version)>"`, so a version bump
produces a new finding instead of silently inheriting an exception.

Severity rules (config-driven where sensible):

| Severity | Examples |
|---|---|
| CRITICAL | KEV CVE affecting an installed version; any secret in public repo; unexpected public listener; SSH password auth or root login enabled; failed unit > 15 min; backup > 10 days; cert < 7 days; disk > 90 %; opencode reachable outside tailnet |
| WARN | High/critical CVE not in KEV; flake.lock > 30 days; backup check > 14 days; disk > 80 %; store > 60 GiB; generations > 20; allowlist expiring/expired; lint/docs drift; partial scan |
| INFO | inventory, versions, counts, KEV watchlist |

Allowlist (`allowlist.toml`, versioned, public-repo safe):

```toml
[[exception]]
id = "SEC-01:4f3c2a91b7d0e6c8"
expires = 2027-01-31
reason = "Rauthy admin API intentionally bound for tailnet access only"
approved_by = "owner"
```

Rules:

- `id`, `expires`, `reason`, `approved_by` mandatory.
- TTL > 90 days → `concierge allowlist lint` fails.
- Expired exception → finding returns as WARN (never silently disappears).
- Exceptions never downgrade severity, they only mark `allowlisted=true` and move the
  item to the annex. CRITICAL allowlisted items still appear in the TL;DR.
- Lint runs in CI and in every report.

## 10. Report

Output per run:

```
/var/lib/concierge/runs/2026-W43/
├── report.md            # French, user-facing, < 50 KiB
├── report.html          # same content, inline CSS, mobile-first
├── findings.json        # complete machine-readable set
├── collector.json       # copied snapshot input (0640)
└── raw/                 # vulnix.json, osv.json, gitleaks.json, kev.json, lint.txt
/var/lib/concierge/latest -> runs/2026-W43
```

Rendering: Go `text/template` for Markdown, `html/template` for HTML, same view model,
deterministic sorting (severity → check → subject). Atomic write (`tmp` + rename).
HTML has no remote assets. No secret values, ever.

Sections: TL;DR, action required, house state, growth/aging, security & CVE, repo &
home, chores performed, annex (checks run, checks failed, allowlisted items).

## 11. Notification

### Gotify

- New dedicated application token, created manually by the owner in Gotify UI, stored as
  `CONCIERGE/GOTIFY_TOKEN` in `secrets/secrets.yaml` (sops), declared in
  `hosts/beaver/system/secrets.nix` with `owner = "concierge"; mode = "0400";`.
- POST `/message?token=…`, `priority` 8 for CRITICAL, 5 for WARN (opt-in), max 8 KiB,
  truncated summary + "full brief by email".
- CRITICAL is sent once per finding per week (state in `state/notified.json`), not on
  every re-render.

### Email

- Local Postfix (`sendmail -oi -t`), multipart text + HTML, subject
  `[beaver] Concierge — 2026-W43 — 2 actions`.
- Recipient from config. Empty action list still sends the weekly brief (proof of life).

### Silence alert

Add group `conciergeSilence` to `hosts/beaver/system/services/monitoring/alerts.nix`:

```promql
time() - node_systemd_timer_last_trigger_seconds{name="concierge.timer"} > 8 * 86400
```

`noDataState = "Alerting"`, `for = "1h"`, receiver Gotify. Node exporter's systemd
collector is already enabled. This catches a timer that never fired as well as one that
stopped.

### Failure notifier

`concierge-notify-failure@.service`: Gotify CRITICAL + email with the failed unit,
`journalctl -u <unit> -n 20`, and the last journal entries. Runs on `OnFailure=` of both
collect and analyze.

## 12. Agent logbook

### Location and permissions

```
/var/lib/agent-journal/                       root:concierge 2770 (setgid)
├── journal-2026-10.jsonl                     0660
├── journal-2026-11.jsonl
├── handoff/beaver.json                       current handoff pointer
└── state/last-hash
```

Root agents and the unprivileged concierge must both append; hence group-write +
setgid. Appends use `O_APPEND`, `flock`, and an explicit `0660` mode.
Monthly files, gzip after 3 months, delete after 12 months.

### Entry schema

```json
{
  "ts": "2026-10-24T06:12:00Z",
  "host": "beaver",
  "agent": "opencode",
  "session": "ses_abc123",
  "kind": "action",
  "summary": "Rotated the monitoring cert and verified nginx reload",
  "targets": ["acme/monitoring.justalternate.com", "nginx"],
  "result": "ok",
  "tags": ["tls", "nginx"],
  "report": "2026-W43",
  "prev": "9f2c…",
  "hash": "41ab…"
}
```

- `kind`: `action` | `decision` | `observation` | `handoff`.
- `hash = sha256(canonical_json_without_hash || prev)`; genesis `prev = "GENESIS"`.
  `concierge journal verify` fails on any chain break.
- Limits: summary 2 KiB, whole entry 4 KiB; `details` optional free-form text.
- Scrubber rejects entries matching: `AGE-SECRET-KEY-`, `-----BEGIN .*PRIVATE KEY-----`,
  `(?i)(password|token|secret|api[_-]?key)\s*[=:]`, bearer/JWT patterns, long base64/hex
  blobs (> 40 chars). No override flag; log a summary instead.
- Never logs raw command output. No secrets, no private keys, no tokens.

### CLI

```
concierge journal add --agent opencode --kind action --summary "..." \
                      --targets nginx,tls --result ok --tag tls
concierge journal tail [-n 20] [--host beaver]
concierge journal search --tag mail --since 2026-09-01
concierge journal handoff --from opencode --to next --note "finish CVE triage"
concierge journal handoff show
concierge journal verify
concierge journal export --since 2026-01-01   # stdout, for a future private repo
```

### AGENTS.md convention

Add to `/root/nixcfg/AGENTS.md` and `hosts/beaver/home/agent-AGENTS.md`:

- At session start: `concierge journal tail -n 20` and `concierge journal handoff show`.
- After any non-trivial action or decision: append one entry (what, why, result).
- Before ending a multi-step task: leave a `handoff` if work remains.
- Never paste secrets, tokens, keys, or raw logs; describe them.

### Multi-host

Out of MVP scope. `journal export` is designed so a private git repo or Tailscale rsync
can sync later. The journal **never** goes into the public `nixcfg` repo.

## 13. Autonomy and chores

`mode = observe` in the MVP: zero writes outside `/var/lib/concierge`,
`/var/cache/concierge`, and the journal.

`propose` adds a "Proposals" section with concrete diffs/commands, still applies nothing.

`act` runs only entries enabled in config:

| Chore | Safe? | Notes |
|---|---|---|
| prune report dirs > `reports_days` | yes | only under `/var/lib/concierge/runs` |
| prune cache > `cache_days` | yes | only under `/var/cache/concierge` |
| `nix-collect-garbage` (no `-d`) | yes-ish | unreferenced store paths only; keep disabled by default |
| prune journal > 12 months | yes | journal subcommand, compressed |
| rotate/compress journal | yes | monthly |

Explicitly **not** chores:

- NixOS GC/generations: already automatic (`nix.gc` weekly, `--delete-older-than 7d`,
  which deletes generations older than 7 days — concierge reports generation count/age
  and may propose raising it; it never deletes generations).
- `nixos-rebuild switch`, `nix flake update`, service restart/stop.
- restic prune/restore/check, database dumps.
- firewall/DNS/Tailscale changes, user/key changes, deleting data outside state dirs.

## 14. Failure handling

- Any scanner failure → `partial=true` in findings, WARN notification, explicit
  "not measured" line in the annex. Never "all clear".
- Missing collector output/nonce mismatch → analyze aborts with exit 1, failure notifier
  fires.
- Re-run in the same ISO week: overwrite the run directory atomically, keep
  `latest`; notify only new/changed CRITICALs.
- Timeouts: per-check 5 min, whole analyze 15 min (`TimeoutStartSec`).
- No overlap: systemd will not start an active unit again; add a lock file for manual
  runs.
- Offline mode (`--offline`) uses cached intel and is used by tests and by the failure
  notifier.

## 15. Security controls / threat model

| Risk | Control |
|---|---|
| Malicious/compromised CVE feed → RCE | parsed by unprivileged `concierge`, no caps, strict FS |
| Secret leak via report/email/journal | redaction, scrubber, no raw scanner payloads in report; report 0640 |
| Public repo leak | gitleaks weekly + optional GitHub CI; reports never committed |
| Prompt injection into a future LLM triage | MVP has no LLM; phase 6 local-only, no webfetch/shell |
| Agent with broad permissions | SEC-09 checks opencode exposure; REPO-09 flags `bash/edit/webfetch: allow` as a review item |
| Tampering with the logbook | hash chain + `journal verify` in each weekly run (WARN on break) |
| Report exfiltration | never served by nginx; if a portal is ever wanted, tailnet + Rauthy only |
| Root collector compromise | no network, `CapabilityBoundingSet=""`, read-only `/root`, writes only `/run/concierge` |

The concierge must never be added to `trusted-users` and never gets the sops age key.
Only the Gotify app token is exposed to it.

## 16. Testing and acceptance

- `go test ./...`: severity mapping, finding IDs, allowlist expiry/lint, scrubber,
  hash chain, deterministic render (golden files).
- `concierge analyze --offline --fixtures testdata/` with fake collector/vulnix/osv/KEV
  → stable Markdown/HTML.
- Failure injection: fake failed unit, fake unexpected listener, gitleaks test repo with
  a dummy secret, expired allowlist entry.
- Manual dry run: `systemctl start concierge-collect concierge-analyze` with
  `--no-notify`; inspect report and `journal verify`.
- Silence alert proof: skip one scheduled run in a test window; confirm Grafana fires
  after the configured delay (temporarily lower threshold if needed).
- Hardening check: `systemd-analyze security concierge-collect concierge-analyze`.

Acceptance for MVP:

- 3 consecutive weekly briefs, each < 10 min, < 50 KiB Markdown.
- No false CRITICAL in the first month; every CRITICAL has a reproducible check ID.
- No secret value appears in report/email/journal/logs (grepped in tests).
- Timer silence alert verified once.
- Retention verified: old run dirs removed, cache bounded.
- `nixfmt . -c`, `deadnix . -f`, `statix check .`, `nix flake check` clean for the new code.
- `nixos-rebuild dry-activate` lists only the new units/timer/user.
